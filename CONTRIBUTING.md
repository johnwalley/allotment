# Contributing to Allotment

Thanks for your interest in contributing! Bug reports, feature requests and pull requests are all welcome.

Please read and follow the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Reporting bugs and requesting features

Open an [issue](https://github.com/johnwalley/allotment/issues). For bugs, a minimal reproduction (for example a CodeSandbox or StackBlitz link) makes it much quicker to find and fix the problem. Please include the versions of Allotment, React and your browser.

## Development setup

You'll need Node.js 20 or 22 (the versions tested in CI).

```sh
git clone https://github.com/johnwalley/allotment.git
cd allotment
npm install
```

### Useful commands

| Command                   | Description                                             |
| :------------------------ | :------------------------------------------------------ |
| `npm run storybook`       | Start Storybook at http://localhost:6006 to try changes |
| `npm test`                | Run the Jest test suite                                 |
| `npm run build`           | Build the library and type declarations into `dist/`    |
| `npm run build-storybook` | Build a static version of Storybook                     |

Storybook is the quickest way to develop and check a change. Stories live in `stories/`, and adding one for new behaviour is encouraged.

### Documentation site

The documentation site in `website/` uses [Docusaurus](https://docusaurus.io/) and has its own dependencies:

```sh
cd website
npm install
npm start
```

If your change affects the API, please update both `README.md` and the relevant page in `website/docs/`.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Make your change, adding or updating tests where it makes sense.
3. Check that `npm run build` and `npm test` pass. CI runs both on every pull request.
4. Open a pull request describing the change and the motivation for it.

A pre-commit hook formats staged files with Prettier and runs ESLint on TypeScript files.

### Commit messages

Releases and the [changelog](./CHANGELOG.md) are generated by [release-please](https://github.com/googleapis/release-please) from commit messages, so please use [Conventional Commits](https://www.conventionalcommits.org/):

- `fix: …` for bug fixes (patch release)
- `feat: …` for new features (minor release)
- `docs: …`, `chore: …`, `test: …` and similar for changes that don't need a release
